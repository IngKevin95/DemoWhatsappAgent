# HU-031: Input Validation & Sanitization

## Descripción

Validar y sanitizar texto de entrada de usuarios antes de procesarlo con LLM o herramientas. Remover o escapar scripts, SQL, y otros payloads peligrosos.

## AC-1: Remove SQL Injection Attempts

**Given** Usuario envía mensaje: `'; DROP TABLE cases; --`  
**When** webhook procesa el mensaje  
**Then**
- Sanitizer detecta SQL keywords (DROP, DELETE, INSERT, etc.) y caracteres peligrosos (`;`, `--`, etc.)
- Payload transformado a: `"DROP TABLE cases"` (remove special chars)
- LLM recibe texto limpio: "DROP TABLE cases"
- Log registra: original_input (redacted), sanitized_input, action="sql_injection_detected"

## AC-2: Remove Script Tags & XSS

**Given** Usuario envía: `<script>alert('xss')</script>`  
**When** webhook procesa  
**Then**
- Sanitizer detecta HTML tags (`<`, `>`) y script keywords
- Payload transformado a: `"scriptalertxssscript"` (remove tags)
- LLM recibe: "scriptalertxssscript"
- Log registra: xss_attempt_detected, sanitized_output

## AC-3: Allow Normal Messages

**Given** Usuario envía mensaje válido: `Quiero saber el precio del módulo X`  
**When** webhook procesa  
**Then**
- Sanitizer validates: no dangerous patterns
- Message pasa sin cambio
- Procesamiento normal continúa

## AC-4: False Positives (Characters That Look Dangerous But Aren't)

**Given** Usuario envía mensajes legítimos que contienen caracteres que parecen peligrosos:
- `SELECT * FROM public_documentation` (SQL keyword en contexto normal)
- `WHERE can I find pricing?` (SQL keyword como palabra común)
- `Use <name> format` (angle brackets pero no HTML tag)  
**When** webhook procesa  
**Then**
- Sanitizer permite pasar (no es una inyección, es contexto semántico válido)
- Whitelisting approach distingue: `<script>` (blocked) vs `<name>` (allowed)
- Log registra: potential_false_positive, allowed_reason="valid_context"

## Dependencias

- Ninguna. Independiente.

## Notas de Implementación

- Middleware de input validation en `agent/middleware/input_validator.py`
- Aplicar en `main.py::recibir_webhook()` después de rate limit
- Blacklist approach: remover caracteres peligrosos (`;`, `--`, `<`, `>`, `()`, etc.)
- Whitelist approach: solo permitir alfanuméricos + espacios + puntuación básica (recomendado)
- Config: `INPUT_VALIDATION_ENABLED=true` en `.env`
- Log sanitized vs original (pero nunca loguear payload completo si contiene tokens)
