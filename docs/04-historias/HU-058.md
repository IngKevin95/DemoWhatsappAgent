# HU-058: Notificación WhatsApp al líder de infraestructura ante fallo técnico

## Descripción
**Como** líder de infraestructura
**Quiero** recibir un WhatsApp cuando el bot detecta un fallo técnico de un servicio externo (Google/Calendar)
**Para que** pueda intervenir de inmediato (por ejemplo, re-autorizar el token) sin depender de que alguien revise los logs.

## Criterios de Aceptación

### Scenario 1: Fallo técnico con líder infra configurado (happy path)
- **Given** que existe el parámetro `whatsapp_lider_infra` con un número válido
- **When** el bot maneja un fallo técnico de Google/Calendar
- **Then** se envía un WhatsApp a ese número con el detalle del error, el área afectada y el contacto involucrado
- **And** el envío se hace además del correo a infra que ya existe.

### Scenario 2: Parámetro no configurado (edge)
- **Given** que el parámetro `whatsapp_lider_infra` no existe o está vacío
- **When** el bot maneja un fallo técnico de Google/Calendar
- **Then** no se intenta enviar WhatsApp a infra
- **And** el resto del manejo (log, correo, escalamiento) se ejecuta normalmente
- **And** se registra en log que no había número de infra configurado.

### Scenario 3: Fallo en el envío del WhatsApp de alerta (error)
- **Given** que el parámetro `whatsapp_lider_infra` está configurado
- **When** el envío del WhatsApp a infra falla (error de red o de la API de Meta)
- **Then** el error se captura y se registra con `logger.error`
- **And** no interrumpe el flujo de escalamiento ni el manejo del fallo original.

## Detalles Técnicos
- Nuevo parámetro en la tabla `parametros`: clave `whatsapp_lider_infra`.
- Reutilizar `_enviar_whatsapp_directo(telefono, texto)` para el envío.
- El envío ocurre dentro del manejador generalizado de fallos de Google (HU-057), envuelto en try/except propio.
- Seed del parámetro en `init-db/schema.sql` (o migración) y editable desde NocoDB.
