# HU-030: Rate Limiting en Webhook

## Descripción

Proteger el webhook de bot contra ataques DDoS básicos limitando requests por IP. Máximo 10 requests por minuto por IP; después, retornar 429 Too Many Requests.

## AC-1: Rate Limit Enforced por IP

**Given** IP ha enviado 10 requests en el último minuto  
**When** intenta enviar el 11° request  
**Then**
- Webhook retorna 429 "Too many requests. Límite: 10 req/min por IP"
- Request NO se procesa (no llega a Gemini ni herramientas)
- Log registra: source_ip, attempts_count, timestamp

## AC-2: Rate Limit Reset Después de 1 Minuto

**Given** IP fue rate limitado hace 1 minuto  
**When** envía el siguiente request  
**Then**
- Contador reset a 0
- Request se procesa normal (HTTP 200)
- Log registra: reset_event, source_ip, timestamp

## AC-3: Rate Limit NO Afecta IPs Diferentes

**Given** IP-A envió 10 requests (limitada)  
**When** IP-B envía request  
**Then**
- IP-B se procesa normal (no está limitada)
- Cada IP tiene contador independiente

## AC-4: Proxy/CDN IP Handling (Edge Case)

**Given** Cliente accede vía proxy o CDN (headers X-Forwarded-For presente con lista: `client_ip, proxy_ip, cdn_ip`)  
**When** envía requests  
**Then**
- Rate limiter extrae client_ip correcto (primer valor en X-Forwarded-For)
- Contador es por client_ip real, no por proxy IP
- Log registra: client_ip (extracted), proxy_chain, trusted_proxy_verified

## Dependencias

- Ninguna. Independiente.

## Notas de Implementación

- Middleware de rate limiting en `agent/middleware/rate_limiter.py` (ya existe parcial)
- Aplicar en `main.py::recibir_webhook()` antes de validar firma Meta
- Token bucket o sliding window algorithm (sliding window es OK para demo)
- Config: `RATE_LIMIT_REQUESTS=10` y `RATE_LIMIT_WINDOW_SECONDS=60` en `.env`
- Log en formato JSON con fields: source_ip, requests_count, action="rate_limited"
