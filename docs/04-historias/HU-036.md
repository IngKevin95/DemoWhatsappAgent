# HU-036: Consentimiento persistido en el contacto

## Descripción

Persistir en `Contacto` el estado del consentimiento de tratamiento de datos (habeas data): no
preguntado (NULL), aceptado (True) o rechazado (False), con la marca de tiempo. Base para el gate
de EP-008.

## AC-1: Estado inicial no preguntado

**Given** un contacto recién creado
**When** se consulta su consentimiento
**Then**
- `consentimiento` es NULL y `consentimiento_en` es NULL

## AC-2: Registrar aceptación

**Given** un contacto con `consentimiento` NULL
**When** se llama `registrar_consentimiento(telefono, True)`
**Then**
- `consentimiento=True`, `consentimiento_en=now`

## AC-3: Registrar rechazo

**Given** un contacto con `consentimiento` NULL
**When** se llama `registrar_consentimiento(telefono, False)`
**Then**
- `consentimiento=False`, `consentimiento_en=now`

## AC-4: Contacto inexistente (edge)

**Given** un teléfono sin contacto registrado
**When** se llama `registrar_consentimiento`
**Then**
- Se crea/upserta el contacto mínimo y se registra el consentimiento, sin fallar

## Dependencias

- Ninguna (columnas sobre `Contacto`, que ya existe).

## Notas de Implementación

- `Contacto.consentimiento = Column(Boolean, nullable=True)` y
  `consentimiento_en = Column(DateTime, nullable=True)` en `agent/db.py`.
- Helper `registrar_consentimiento(telefono, valor)` en `agent/memory.py` (reusar `_upsert_contacto`).
- Migración `ALTER TABLE contactos ADD COLUMN consentimiento boolean, ADD COLUMN consentimiento_en ...`.
- Upgrade path: si legal exige versión de política, migrar a tabla `consentimientos` versionada.
