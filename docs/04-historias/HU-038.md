# HU-038: Enviar botones Sí/No

## Descripción

Añadir al provider de WhatsApp la capacidad de enviar mensajes interactivos con botones de respuesta
(reply buttons) de la Meta Cloud API. Hoy solo se envía texto. Requisito del gate de consentimiento
(EP-008).

## AC-1: Envío de botones con la forma de Graph API

**Given** un teléfono destino y un texto con una lista de botones `[(id, título), ...]`
**When** se llama `enviar_botones(telefono, texto, botones)`
**Then**
- Se hace POST a la API de Meta con `type="interactive"`, `interactive.type="button"`,
  `interactive.body.text=texto` y un `action.buttons[]` con cada `reply.id`/`reply.title`

## AC-2: Botón Sí/No de consentimiento

**Given** el texto de política habeas data
**When** se envían los botones `[(habeas_si, "Sí, acepto"), (habeas_no, "No")]`
**Then**
- El body contiene exactamente esos dos reply buttons con esos ids

## AC-3: Límite de 3 botones (edge)

**Given** una lista de más de 3 botones
**When** se llama `enviar_botones`
**Then**
- Se rechaza (ValueError) — la Cloud API admite máximo 3 reply buttons

## AC-4: Fallo de red del provider (error)

**Given** la API de Meta devuelve error HTTP
**When** se envía
**Then**
- Se propaga/loguea el error igual que `enviar_mensaje` (mismo manejo actual), sin romper el caller

## Dependencias

- Ninguna.

## Notas de Implementación

- Método `enviar_botones(telefono, texto, botones)` en `ProveedorWhatsApp` (base.py) y `ProveedorMeta`
  (meta.py). Reutiliza headers/URL de `enviar_mensaje`.
- Chequeo runnable: test que arma el body y verifica su forma (sin llamar a la red real).
