# HU-028: Monitoring & Health Checks

## Descripción

Implementar health check endpoints y métricas Prometheus para monitorear bot en producción. Incluye uptime, latency, error rate, y alertas si algo falla.

## AC-1: Health Check Endpoint

**Given** Monitor o LB quiere verificar que bot está healthy  
**When** GET /health  
**Then**
- Returns 200 OK con JSON:
  ```json
  {
    "status": "healthy",
    "timestamp": "2026-07-14T10:00:00Z",
    "uptime_seconds": 3600,
    "version": "v1.0.0",
    "dependencies": {
      "postgres": "ok",
      "gemini": "ok",
      "google_calendar": "ok"
    }
  }
  ```
- If any dependency fails: status="degraded", HTTP 503

## AC-2: Readiness Endpoint

**Given** Deployment checks readiness  
**When** GET /ready  
**Then**
- Returns 200 if app ready to accept traffic
- Returns 503 if still warming up or dependencies not ready
- Used by K8s/Docker Compose to route traffic only to ready pods

## AC-3: Prometheus Metrics Endpoint

**Given** Prometheus scraper queries metrics  
**When** GET /metrics  
**Then**
- Returns Prometheus format metrics:
  - `demobot_webhook_requests_total{method="POST"}`: total requests
  - `demobot_webhook_latency_seconds`: request latency histogram
  - `demobot_errors_total{type="gemini_timeout"}`: error counts by type
  - `demobot_active_conversations`: gauge
  - `demobot_rate_limit_triggers_total`: rate limit violations
  - `demobot_tool_calls_total{tool="escalar_a_humano"}`: tool invocations

## AC-4: Alerting Rules

**Given** Prometheus alerts configured  
**When** condition triggered  
**Then**
- Alert: P99 latency > 5s → warning
- Alert: error_rate > 1% → critical
- Alert: uptime < 1 hour → warning (fresh crash)
- Alert: rate_limit_triggers > 10/min → investigate (attack?)
- Alerts sent to Slack channel (ops-alerts)

## Dependencies

- Requiere Prometheus installed (local o managed service)
- Requiere Grafana (opcional, para dashboards)
- Requiere `prometheus-client` Python package

## Notas de Implementación

- Health check: simple DB query + external service ping
- Readiness: similar pero stricter (all deps must be OK)
- Prometheus: instrument code with `@prometheus_client.histogram`, `counter`, `gauge`
- Alerts: Prometheus AlertManager or cloud provider alerts (CloudWatch, etc.)
- Dashboard: Grafana dashboard with main metrics (uptime, latency, error rate, throughput)
- Retention: keep metrics for 15 days minimum
