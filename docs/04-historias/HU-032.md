# HU-032: Audit Logging en High-Stakes Tools

## Descripción

Todas las decisiones críticas (escalación, agendar cita, consultar licencia, reclasificar caso) deben quedar registradas en tabla de auditoría con quién, qué, cuándo, y resultado.

## AC-1: Escalar a Humano — Audit Log

**Given** Usuario invoca "Quiero hablar con un agente"  
**When** herramienta `escalar_a_humano()` ejecuta  
**Then**
- Audit table `audit_logs` registra:
  - user_id: ID de usuario en WhatsApp
  - user_phone: teléfono usuario
  - tool_name: "escalar_a_humano"
  - timestamp: ISO 8601 UTC
  - action: "create_case"
  - result: "case_created" | "failed"
  - case_id: si exitoso
  - error_msg: si falló (sin stack trace completo, solo mensaje)
- Log JSON: `{"user_id": "...", "tool": "escalar", "result": "success", "case_id": "..."}`

## AC-2: Agendar Cita — Audit Log

**Given** Usuario invoca "Agendar una consultoría"  
**When** herramienta `agendar_cita()` ejecuta  
**Then**
- Audit table registra:
  - user_id, user_phone, tool_name: "agendar_cita"
  - timestamp, action: "schedule_event"
  - result: "event_created" | "failed"
  - event_id: Google Calendar event ID si exitoso
  - event_datetime: fecha/hora agendada
  - error_msg: si falló

## AC-3: Consultar Licencia — Audit Log

**Given** Usuario invoca "¿Hasta cuándo tengo soporte?"  
**When** herramienta `consultar_licencia()` ejecuta  
**Then**
- Audit table registra:
  - user_id, user_phone, tool_name: "consultar_licencia"
  - timestamp, action: "check_license"
  - result: "valid" | "expired" | "not_found"
  - license_status: valor retornado
  - error_msg: si falló

## AC-4: Reclasificar Caso — Audit Log

**Given** Soporte reclasifica caso de "Técnico" a "Comercial"  
**When** herramienta `reclasificar_caso_sin_licencia()` ejecuta  
**Then**
- Audit table registra:
  - user_id: Soporte agent ID
  - tool_name: "reclasificar_caso_sin_licencia"
  - timestamp, action: "reclassify_case"
  - case_id, old_category, new_category
  - result: "success" | "failed"

## Dependencias

- Requiere tabla DB: `audit_logs` (schema en migration script)
- Requiere `agent/middleware/audit_logger.py` (ya existe parcial)
- Requiere actualización de todas las funciones en `tools.py`

## Notas de Implementación

- Tabla: `audit_logs(id, user_id, user_phone, tool_name, timestamp, action, result, metadata_json, error_msg, created_at)`
- Metadata_json: flexible dict para campos adicionales (case_id, event_id, license_status, etc.)
- Never log: API keys, OAuth tokens, passwords, full stack traces
- Async logging: no bloquear herramienta si DB lenta (queue + async write)
- Retention: 90 días (compliance mínimo)
- Query support: auditor debe poder: `SELECT * FROM audit_logs WHERE tool_name='escalar_a_humano' AND timestamp > '2026-07-14'`
