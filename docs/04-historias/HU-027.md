# HU-027: CI/CD Pipeline

## Descripción

Crear GitHub Actions workflow que ejecute tests, construya imagen Docker, y deployee a staging/production automáticamente en cada push a main.

## AC-1: Test Stage (CI)

**Given** Developer hace push a rama feature  
**When** GitHub Actions trigger  
**Then**
- Checkout código
- Install dependencies: `pip install -r requirements.txt`
- Run tests: `pytest -v --cov`
- Report coverage: >70% required, else fail
- Security scan: SAST (bandit o similar)
- All must pass before proceeding

## AC-2: Build Stage

**Given** Tests pasan  
**When** CI continúa  
**Then**
- Build Docker image: `docker build -t demobot:${GITHUB_SHA} .`
- Tag image: `demobot:latest`, `demobot:${VERSION}`
- Push to registry (Docker Hub o GitHub Container Registry)

## AC-3: Deploy Stage (Staging)

**Given** Image built and pushed  
**When** PR merged to main  
**Then**
- Deploy to staging environment (AWS ECS, DigitalOcean, etc.)
- Health checks: endpoint `/health` returns 200
- Smoke tests: bot responds to sample messages
- If deploy fails: rollback previous version

## AC-4: Deploy Runbook

**Given** Deployment complete  
**When** team needs reference  
**Then**
- Runbook documents:
  - How to manual deploy
  - How to rollback
  - Emergency procedures
  - Monitoring checklist

## Dependencias

- Requiere `.github/workflows/ci-cd.yml` (GitHub Actions)
- Requiere credentials: Docker registry, cloud provider (AWS/DO/etc.)
- Requiere staging environment already setup

## Notas de Implementación

- Workflow triggers: push to main, pull request, manual dispatch
- Environment variables: stored in GitHub Secrets (never hardcoded)
- Notifications: Slack on failure (opcional, nice-to-have)
- Deployment tool: Docker compose, Helm, or cloud provider CLI
- Rollback: keep previous 3 image versions, easy rollback
