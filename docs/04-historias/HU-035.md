# HU-035: Mensaje ligado a su conversación

## Descripción

Hoy `Mensaje` (en `agent/memory.py`) se relaciona solo por `telefono`. Añadir `conversacion_id`
(FK→conversaciones) para que cada mensaje pertenezca a una conversación, cumpliendo la regla de
dominio "todo mensaje pertenece a una conversación".

## AC-1: Mensaje persiste con su conversación

**Given** un contacto con conversación abierta (id conocido)
**When** se guarda un mensaje con `guardar_mensaje(telefono, role, content, conversacion_id=<id>)`
**Then**
- La fila en `mensajes` tiene `conversacion_id=<id>`

## AC-2: Historial sigue funcionando por teléfono

**Given** varios mensajes guardados con su `conversacion_id`
**When** se llama `obtener_historial(telefono)`
**Then**
- Devuelve los mensajes en orden cronológico (comportamiento actual intacto)

## AC-3: Back-compat con mensajes sin conversación (edge)

**Given** mensajes antiguos con `conversacion_id` NULL
**When** se consultan
**Then**
- No fallan; `conversacion_id` es nullable

## Dependencias

- HU-034 (entidad Conversación debe existir).

## Notas de Implementación

- `Mensaje.conversacion_id = Column(Integer, ForeignKey("conversaciones.id"), nullable=True)` en
  `agent/memory.py`.
- `guardar_mensaje` acepta `conversacion_id` opcional (default NULL para no romper llamadas actuales).
- Migración `ALTER TABLE mensajes ADD COLUMN conversacion_id` para prod.
